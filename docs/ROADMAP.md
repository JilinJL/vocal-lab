# VocalLab 路线图

## 已发布的 v1.0.0

VocalLab 是一个网页练声工具。v1.0.0 实现了实时音高监测、曲线回看、A4 校准、示例曲线和 88 键参考钢琴。项目使用 Vue 3、TypeScript 和 Vite，由 GitHub Pages 提供 HTTPS 访问。`main` 推送会触发自动测试与部署，开发时可用 `pnpm dev`，发布前用 `pnpm test && pnpm build` 检查测试、类型和生产构建。

- [在线使用](https://jilinjl.github.io/vocal-lab/)
- [v1.0.0 发布说明](https://github.com/JilinJL/vocal-lab/releases/tag/v1.0.0)

## v1.1（开发实现与验收中）

用户可以在安卓和 iPhone 上打开 VocalLab，选择舒适的音高范围，听示范并逐音跟唱，看到每个音的判定，再练唱得最不稳的音。用户也可以把 MIDI 或单人清唱导入为参考旋律，选一小段循环跟唱。文件、检测和练习记录均在本机处理。

| 里程碑 | 交付 | 依赖 |
| --- | --- | --- |
| A · 音频底座 | 统一音频时钟、带采集时间戳的音高帧、开麦与停麦可靠 | 现有自由监测 |
| B · 手机可用 | 安卓 Chrome 和 iPhone Safari 真机可练，支持主屏幕安装 | 布局可与 A 同时开发，音频验收基于 A |
| C · 逐音练习 | 音域选择、试听、跟唱打分、结果及错音重练 | A；手机验收基于 B |
| D · 歌曲跟练 | MIDI 和清唱导入、片段循环、沿用练习评分 | C 的评分、时间轴与状态机 |

B 和 C 各可出一个预览版。A–D 的验收都通过后发布 v1.1。安卓和 iPhone 的使用入口先采用移动网页和主屏幕应用，独立安装包安排在 v1.2+。

## A · 音频底座

1. 给 `src/audio/pianoSynth.ts` 和 `src/composables/useMicrophonePitch.ts` 注入同一个惰性创建的 `AudioContext`。点击开麦或试听时启动音频。停麦释放节点和输入 track；共享上下文由应用统一管理。为参考音提供可调度的起止时间和取消句柄。
2. 在音频采集边界输出 `PitchFrame { time, frequency, clarity, rms }`。`time` 是音频时钟上的采集窗口中心，后到的 Worker 消息仍使用原始时间戳。结果页、曲线和音符排程都能从这个时间轴换算。评分使用检测帧，曲线可独立平滑。
3. 复用 `src/audio/yinDetector.ts` 和 `src/audio/pitchMath.ts`。先把分析频率控制在 25–50 Hz，并实测手机上的处理耗时和掉帧。预算不足时再减少分配，或用 AudioWorklet 采集 PCM、由 Web Worker 跑 YIN。保留 AnalyserNode 路径，并检查生产部署下的 Worker 资源路径。
4. 区分用户拒绝、无输入设备和音频中断。处理快速连点、启动中取消、卸载后权限回调和输入设备失效，确保最多一个输入会话和一条采集循环。
5. 先给频率换算和 YIN 加测试。覆盖常用音、不同采样率、A4 校准的两端、低音和高音的边界、静音及带谐波信号。确认检测范围随 A4 校准调整，并为边界音的偏差留空间。

验收时确认权限拒绝后可重试，反复启停只有一个采集会话，停麦后钢琴仍可使用。用合成音检验检测时间戳和换算，在两台目标手机上各测 5 分钟，记录设备、处理耗时和卡顿。

## B · 移动端 Web

- 手机竖屏把开始按钮、当前音名和曲线放在首屏。A4、曲线窗口和自动跟随放入设置。钢琴默认显示中音区一个八度，提供独立的八度切换按钮。用 `100dvh` 与安全区处理横竖屏，覆盖 320 px 窄屏。
- 曲线可点按查音、横拖回看。琴键触控支持按下和释放，取消触控或切后台时释放按住的音。测试琴键、曲线和页面滚动之间的手势冲突。
- 增加 PWA manifest、图标与 Service Worker。在 `/vocal-lab/` 下验证安装入口、缓存范围和版本更新。缓存应用壳及练习所需资源，采样缺失时回退到合成参考音；字体加载失败时使用系统字体。
- 回到前台时显示「继续」。从当前音重来，避免跳过音符或将中断判作 Miss。保存音域、速度、A4、音量等设置，校验从本地存储恢复的值。

验收覆盖安卓 Chrome 和 iPhone Safari 真机上的开麦、弹琴及曲线回看，包含浏览器与主屏幕两种入口、后台恢复和已缓存后的断网启动。记录设备及系统版本，同时验证桌面键盘和曲线交互。

## C · 逐音练习和评分

### 流程

1. 在「自由监测 / 音高练习 / 歌曲跟练」中打开音高练习。默认 `A3–E4`，提供 `C3–G3`、`C4–G4` 两个快捷范围。用户试听后可选起止音。最小范围为单音，检测范围以当前校准下经过验证的音域为准。
2. 首版支持半音阶上行、下行和慢、正常两档。正常速度每个音演示 `0.7s`，离开示范后等待 `0.3s`，跟唱 `1.5s`。先调试听音量，再倒计时开始。支持暂停、继续、重听当前音和结束。
3. 手机外放默认「先听后唱」。示范音明确停止，间隔后才开始计分。耳机模式提供「边听边唱」，目标音和采集范围共用时钟，使用耳机避免演示音进入麦克风。用静默输入检验外放的示范音漏入评分窗口时能否触发误判。
4. 跟唱时显示目标音、当前音、偏高／偏低和进度。每个音结束后锁定判定，结束页给出总分、逐音偏差和「只练错音」。历史记录留在本机，支持清除。

### 初始评分规则

对 `[singStart + 起音宽容, singEnd)` 内的音高帧按时间计算，逐音练习的宽容期先用 `150ms`。有效有声帧要求检测置信度 `≥ 0.8` 且频率有效。清晰但唱错的音仍计入偏差。缺测时间计入未覆盖时长，限制单帧可代表的最大时长，避免掉帧拉高覆盖率。计算 `1200 × log2(实测频率 / 目标频率)`，默认按实际八度计分。

| 判定 | 按顺序匹配的条件 | 文字与颜色 |
| --- | --- | --- |
| Perfect | 平均绝对偏差 ≤ 10¢，有声覆盖 ≥ 60%，音分标准差 ≤ 12¢ | Perfect · 金 |
| Great | 平均绝对偏差 ≤ 25¢，有声覆盖 ≥ 50% | Great · 绿 |
| Good | 平均绝对偏差 ≤ 50¢，有声覆盖 ≥ 40% | Good · 蓝 |
| Miss | 其余情况，包括静默、低置信度和错音 | Miss · 红 |

总分暂用 `100 / 80 / 55 / 0` 的逐音平均。评分阈值集中配置，随合成测试和试唱结果校准。跟唱时显示即时方向，累积至少 `300ms` 有声帧后可显示暂定分档，音结束时锁定。反馈使用文字、颜色和进度，颜色沿用设计 token。暂停、取消、设备中断的音从结果中排除，恢复时重做。

### 工程拆分与验收

- `sequences.ts` 生成音序，`grading.ts` 接收音高帧和目标窗口后返回判定、音分偏差、有声覆盖及稳定度。`scheduler.ts` 用音频时钟驱动「倒计时 → 示范 → 跟唱 → 结算」，界面订阅状态。记录会话设定和 A4 快照。
- 单测覆盖四档边界、静默、只唱短瞬间、唱错半音或八度、有效数据断续，以及温和颤音。在规定时窗测试钢琴串音、暂停恢复、模式切换和重练去重。复用现有曲线绘制能力添加目标音条，在安卓 Chrome 和 iPhone Safari 各完成一整轮练习。

## D · 歌曲跟练

1. **MIDI**。解析 `.mid` 音符、时长、节奏和速度变化，让用户选择旋律轨并试听。对多声部提示选择单一旋律轨。把输入归一为 `{ start, duration, midi }[]`，与练习共用时间轴。
2. **单人清唱**。先支持 WAV 和 MP3，以 `10 MB / 60 秒` 作为预览版上限。用浏览器解码，Worker 离线提取音高并按静音和持续音高分段，显示进度、取消和失败原因。用户先预览识别结果，再开始评分。
3. **练习**。显示目标音条和实唱曲线。支持 A–B 循环、从当前段开始、慢速播放及参考旋律移调，移调和变速后试听与评分用同一份音符数据。跟练可静音参考旋律，或用耳机听参考音。短音的起音宽容按时长缩放，保留有效评分区间；休止符不计分。处理播放、跳转、循环和暂停之后的时间重对齐。
4. **混音歌曲**。带伴奏的 MP3 可作试听或伴奏，评分可配一个 MIDI 或清唱参考轨。自动从完整混音提取主旋律列入后续验证。导入限额、解码失败与储存空间不足都有明确恢复路径，用户可删除本地文件和记录。

验收时使用含变速标记和休止符的 MIDI，以及可核对音符的清唱录音。两端真机各完成导入、试听、选段、跟唱、循环和结果查看。重复循环无明显偏移，损坏文件和提取失败都有可读提示。启动录音和导入文件时用网络面板确认音频未发送至服务器。

## v1.2+ · 原生 App 和扩展

- **Android 与 iOS App**。用 Capacitor 做技术验证，优先确认麦克风权限、音频路由、中断恢复、系统文件选择器以及离线冷启动。带同一批练习与导入样本通过两端真机验证后，再做签名与分发。Android 先验证安装包，iOS 先验证 TestFlight。
- **音域测试**。测舒适低音和高音，生成可改的练习范围。
- **复盘与训练计划**。加本地录音回放、按音统计和薄弱音推荐练习，再考虑练声曲库和分享。
- **混音跟唱**。先用有参考标注的样本测主旋律提取准确率、内存和耗时，再决定端侧方案及覆盖设备。

## 给 GPT 的第一条任务

> 先从里程碑 A 做一个可独立验证的改动。在当前 Vue + TypeScript 项目中，梳理麦克风和钢琴的 AudioContext 创建及清理路径。共享音频时钟、保证停麦会释放输入且钢琴仍能播放，并处理快速连点或启动中取消。给 `pitchMath.ts` 和 `yinDetector.ts` 补基准测试。优先保留监测和钢琴的现有入口。交付变更、构建和测试结果，列出真机验收项。通过后依序完成移动端、练习模式、歌曲导入。

每个里程碑完成时运行构建和测试，记录实测设备与未通过项。发布候选应先在 HTTPS 地址验证静态资源、权限和音频流程，再更新版本号、README 和发布说明。保留可重复使用的合成音、MIDI 和清唱测试样本。
